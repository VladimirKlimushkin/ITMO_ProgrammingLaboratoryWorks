# Конспект: Основы Python — от байткода до типов

## 1. От исходного кода к байткоду

- **REPL** выводит значение любого выражения (expression).
- **Файл** при компиляции не выводит значения выражений напрямую - нужен `print()`.
  - `2 + 3 * 4` => `14` (в REPL выводится сразу, в файле - только через `print`).

### Байткод CPython

- **Assign** - присваивание (`course = "Python"`).
- **Mult()** - умножение (`hours = 4 * 2`).
- **Expression** - вызов функции (`print()`).

**Почему байткод CPython не является машинным кодом процессора?**
Байткод Python - это инструкции для виртуальной машины Python (PVM), а не для реального процессора. Их читает и выполняет интерпретатор CPython, который уже даёт команды процессору.

## 2. Имена, объекты и сравнение

- `==` сравнивает **значения** объектов.
- `is` сравнивает **id** объектов (идентичность).
- `None` - синглтон, поэтому сравнивается через `is`.
- `b = a` **не создаёт копию** объекта, а создаёт вторую привязку имени к тому же объекту.
- `type()` возвращает класс объекта, `id()` - уникальный идентификатор.
- `"py" + "thon"` сворачивается на этапе компиляции в один объект - одинаковый `id`.

**Вопросы:**
1. Создаёт ли `b = a` копию объекта? - Нет, вторую привязку имени.
2. Что возвращают `type()` и `id()`? - Класс объекта и уникальный идентификатор.
3. Почему `None` сравнивают через `is`, а числа и строки - через `==`? - `None` - синглтон с одним `id`; строки и числа могут существовать в нескольких объектах с одинаковым значением.

## 3. Числовые типы, операции и преобразования

### Эксперимент A: `/` и `//`

- `//` - целочисленное деление, отбрасывает остаток, возвращает целую часть.
- `/` - деление с плавающей точкой, всегда возвращает `float`, даже если результат целый.

### Эксперимент B: Большие int

- `int` в Python - **произвольной точности**: `2 ** 1000` вычисляется без переполнения.
- В Java/C `int` ограничен 32/64 битами => переполнение даёт неверный результат.

### Эксперимент C: Погрешность float

- `0.1 + 0.2 = 0.30000000000000004` — 0.1 и 0.2 в двоичной системе - бесконечные дроби, округляются; сумма накопленных ошибок даёт отклонение.
- **Нельзя** сравнивать `float` через `==`. Используйте `math.isclose(a, b)`.

### Эксперимент D: Bool, complex и явное преобразование

- `bool("False") == True`, потому что **непустая строка всегда истинна**.
- Falsy-значения: `False`, `bool("") == False`.
- `bool(-1) == True`, `bool("False") == True`.

**Контрольные вопросы:**
1. Почему `/` для двух `int` даёт `float`? - `/` - истинное деление, может дать дробный результат; Python всегда возвращает `float`, чтобы не терять точность.
2. Отличие `int("42")` от `int(42.9)`? - Первое парсит строку => `42`; второе отбрасывает дробную часть => `42`.
3. Какие значения из эксперимента D falsy? — `False`, `bool("") == False`. Остальные (`bool(-1)`, `bool("False")`) -> `True`.

## 4. Строки, Unicode и форматирование

**Контрольные вопросы:**
1. Почему `len(symbol)` и `len(symbol.encode("utf-8"))` различаются? - Первое считает символы Unicode, второе - байты. `'Я'` в UTF-8 занимает 2 байта.
2. Что означают границы и шаг в `text[start:stop:step]`? - `start` - индекс начала (включительно, по умолчанию 0); `stop` - индекс конца (не включительно, по умолчанию длина строки); `step` - шаг (по умолчанию 1); отрицательный шаг разворачивает.
3. Почему строка неизменяема, хотя `.upper()` возвращает изменённый текст? - `.upper()` не меняет исходную строку, а создаёт новую и возвращает её; исходная остаётся прежней.

## 5. Информационная карточка вычислительного эксперимента

**Контрольный вопрос:**
Что изменится на уровне объектов и связывания имён после повторного присваивания нового значения уже существующему имени?

- Старый объект отвязывается от имени.
- Если на него больше нет ссылок - он удаляется сборщиком мусора.
- Имя привязывается к новому объекту.
